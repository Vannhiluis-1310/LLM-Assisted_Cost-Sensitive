# Phase 2.1 Context: Kaggle-inspired XGB Magic Baseline

## Phase Boundary

Phase 2.1 strengthens the supervised ML baseline before Phase 3 LLM/RL work. It adds one leakage-safe, Kaggle-inspired XGBoost/LightGBM magic-style baseline to the existing Phase 2 notebook.

This phase is still supervised ML only. It must not implement LLM embeddings, table-to-text serialization, contextual bandit, DQN, RL training, TabNet, FT-Transformer, or full FraudSquad 1st-place ensemble reproduction.

## Why This Phase Exists

The current Phase 2 baseline is clean and cost-sensitive, but it may be challenged as too simple for IEEE-CIS because the dataset has famous strong Kaggle solutions, including cdeotte's XGB Magic notebook and FraudSquad's 1st-place solution.

The goal is not to beat Kaggle SOTA. The goal is to include a stronger supervised baseline that borrows safe ideas from Kaggle feature engineering while keeping the project's own split and cost-sensitive metrics.

## Locked Decisions

- Use the same raw IEEE-CIS files: `data/raw/train_transaction.csv` and `data/raw/train_identity.csv`.
- Use the same left join by `TransactionID`.
- Use the same `TransactionDT` 70/15/15 split from Phase 1/2.
- Update the existing notebook `notebooks/02_baselines_cost_metrics.ipynb`; do not create a new `src/` mirror.
- Add one model family: `xgboost_magic_style` or `lightgbm_magic_style`, with Random Forest fallback only if both libraries are unavailable.
- Feature engineering statistics must be fit on train only, then mapped to validation/test.
- Do not use Kaggle test files, leaderboard artifacts, or post-processing that depends on competition train/test structure.
- Do not claim comparison against Kaggle 1st place unless full reproduction is actually performed under the same evaluation protocol.

## Feature Engineering Scope

Required safe features:

- `amount_cents = TransactionAmt - floor(TransactionAmt)`.
- Count/frequency encodings fit on train for:
  - `card1`
  - `card2`
  - `addr1`
  - `P_emaildomain`
  - `R_emaildomain`
  - `card1_addr1`
- Simple group key:
  - `card1_addr1 = card1 + "_" + addr1`, with missing values explicitly handled.
- Train-fitted `TransactionAmt` group stats:
  - by `card1`: count, mean, std
  - by `card1_addr1`: count, mean, std

Optional only if still simple and leakage-safe:

- A conservative proxy UID such as `card1_addr1_D1_proxy`, without claiming it is a real user identity.
- Additional count encodings for `DeviceType`, `DeviceInfo`, or `id_31` if present and not too sparse.

## Evaluation Requirements

The new baseline must be evaluated with the same Phase 2 functions:

- PR-AUC
- ROC-AUC
- fraud Recall
- fraud Precision
- fraud F1
- confusion matrix
- FN Cost
- FP Cost
- Total Cost
- Cost Saving vs approve-all
- validation-only threshold tuning for `Cost-A`, `Cost-B`, and `Cost-C`

## Report Wording

Use this framing:

> We do not claim to outperform the Kaggle 1st-place solution. The 1st-place solution is treated as an external SOTA reference because it optimizes Kaggle leaderboard ROC-AUC with extensive UID magic, ensemble modeling, and post-processing. Our internal comparison uses the same time-based split and cost-sensitive evaluation for all implemented models. To strengthen the supervised baseline, we include a leakage-controlled XGBoost Magic-style baseline inspired by Kaggle solutions.
