## Technical Design

### Run Configuration

```python

    "smoke": 10_000,
    "sample_100k": 100_000,
    "sample_200k": 200_000,
    "sample_300k": 300_000,
    "full": None,
}
SELECTED_RISK_MODEL = "lightgbm_balanced"
AMOUNT_BIN_QUANTILES = [0.00, 0.50, 0.80, 0.95, 1.00]
MIN_BIN_VALIDATION_ROWS = 100
MIN_BIN_VALIDATION_FRAUD = 5
```

### Level 3: Global Cost-Sensitive Threshold

For each cost config:

1. On validation, evaluate a threshold grid.
2. Select the threshold that minimizes:

```text
Total Cost = FN Cost + FP Cost
FN Cost = sum(TransactionAmt * beta) for fraud predicted approve
FP Cost = sum(TransactionAmt * alpha) for legitimate predicted flag
```

3. Apply the selected threshold to test.

Tie-breaker:

1. lower Total Cost;
2. lower FP Cost;
3. higher fraud Recall;
4. higher threshold for more conservative blocking.

### Level 4: Amount-Bin Dynamic Threshold

Amount bins:

| Bin | Suggested Source |
|---|---|
| `low` | train amount <= q50 |
| `medium` | q50 < train amount <= q80 |
| `high` | q80 < train amount <= q95 |
| `very_high` | train amount > q95 |

Rules:

- Bin boundaries are derived before test evaluation.
- Thresholds are tuned only on validation rows within each bin.
- If a validation bin is too small, fallback to the Level 3 global threshold.
- Test rows are assigned to frozen bins and evaluated with frozen thresholds.

### Closed-Form Threshold Guard

The notebook must include a short markdown note:

```text
The closed-form expected-cost threshold is not amount-dynamic here because
TransactionAmt appears in both C_FN and C_FP and cancels out:
p > alpha / (alpha + beta).
```

This prevents the report from making the wrong claim.
