# Phase 3.2 Plan: LLM-Assisted Hybrid Policy

<objective>
Implement Level 5 of the evaluation framework in a new Colab-ready notebook. Level 5 combines a strong supervised risk score with neutral MiniLM embeddings to adjust or augment the tuned Level 4 dynamic decision policy. It must compare directly against the tuned Level 4 comparator from Phase 3.1b on the same run mode, split, and cost configurations.
</objective>

## Scope

### MVP

- Create `notebooks/05_llm_hybrid_policy.ipynb`.
- Load the tuned Level 4 comparator from Phase 3.1b:
  - `results/phase31b_candidate_metrics_{RUN_MODE}.csv`
  - `results/phase31b_selected_policies_{RUN_MODE}.csv`
  - `results/five_level_comparison_tuned_{RUN_MODE}.csv`
- Load Phase 2 LightGBM risk scores:
  - `results/baseline_scores_{RUN_MODE}.csv`
- Load or create MiniLM embeddings from neutral table-to-text.
- Implement two Level 5 MVP candidates:
  - embedding similarity threshold adjustment;
  - hybrid score threshold.
- Tune hybrid parameters on validation only.
- Apply frozen Level 5 candidates to test.
- Compare Level 5 directly against tuned Level 4.
- Save Level 5 metrics, selected policies, disagreement cases, and figures.

### Stretch Goal

- Add a small meta-policy:
  - `level5_meta_policy_small`
  - input features: LightGBM score, embedding similarity delta, `TransactionAmt`, amount-bin id.
- If train LightGBM scores are unavailable, split validation internally:
  - `meta_train`
  - `meta_validation`
  - test remains untouched until final reporting.
- Add prototype ablation:
  - fraud prototype only;
  - fraud-minus-legit prototype;
  - per-amount-bin fraud prototype.

### Out of Scope

- No LLM fine-tuning.
- No API LLM over the full dataset.
- No risk wording in serialized text.
- No Q-bandit/RL changes.
- No PPO/A2C.
- No test tuning.
- No claim that LLM helps unless Level 5 wins on test metrics.

## Candidate Policies

### Candidate 1: Embedding Similarity Threshold Adjustment

Policy name:

```text
level5_embedding_similarity_threshold_adjustment
```

Steps:

1. Compute prototypes using train embeddings only:

```text
fraud_prototype = mean(embedding_train[y_train = 1])
legit_prototype = mean(embedding_train[y_train = 0])
```

2. Compute similarity delta:

```text
sim_delta = cosine(embedding, fraud_prototype) - cosine(embedding, legit_prototype)
```

3. Standardize `sim_delta` using train or validation statistics saved in metadata.
4. Adjust tuned Level 4 row threshold:

```text
threshold_hybrid = threshold_level4 - gamma * standardized_sim_delta
```

Interpretation:

- More fraud-like embedding lowers the blocking threshold.
- Less fraud-like embedding raises the blocking threshold.

Tune:

```python
GAMMA_GRID = [-0.20, -0.10, -0.05, 0.00, 0.05, 0.10, 0.20]
```

Select `gamma` on validation only for each cost config.

### Candidate 2: Hybrid Score Threshold

Policy name:

```text
level5_hybrid_score_threshold
```

Compute:

```text
hybrid_score = sigmoid(logit(lightgbm_score) + w * standardized_sim_delta)
```

Tune:

```python
W_GRID = [-2.0, -1.0, -0.5, 0.0, 0.5, 1.0, 2.0]
```

For each `w`, tune threshold on validation only and evaluate on test after selection.

### Candidate 3: Small Meta-Policy

Policy name:

```text
level5_meta_policy_small
```

Use only if time permits.

Features:

- LightGBM score
- standardized similarity delta
- `log1p(TransactionAmt)`
- amount-bin one-hot or ordinal id

Training rule:

- If train LightGBM scores are available, train on train and tune threshold on validation.
- If train scores are not available, split validation by row order or `TransactionDT` proxy:
  - first half: `meta_train`
  - second half: `meta_validation`
- Test remains report-only.

Use Logistic Regression or SGDClassifier only. No deep model.

## Selection Rules

For each cost config:

1. Evaluate tuned Level 4 comparator from Phase 3.1b.
2. Tune Level 5 candidates on validation only.
3. Select the Level 5 candidate with lowest validation Total Cost.
4. Tie-break by:
   - lower FP Cost;
   - higher fraud Recall;
   - higher fraud Precision;
   - simpler policy:

```text
threshold_adjustment < hybrid_score < meta_policy
```

5. Apply frozen selected candidate to test.

Claim rule:

- If Level 5 beats tuned Level 4 on test Total Cost or Cost Saving, it can be reported as evidence that MiniLM representation helps the dynamic policy.
- If not, report Level 5 as an honest LLM ablation and keep main contribution on tuned Level 4.
