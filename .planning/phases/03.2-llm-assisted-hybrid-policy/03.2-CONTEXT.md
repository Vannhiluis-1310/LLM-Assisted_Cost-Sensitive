<decisions>
## Locked Decisions

### Notebook and Flow

- Create `notebooks/05_llm_hybrid_policy.ipynb`.
- Keep notebooks 03, 04, and 04b unchanged.
- Use `RUN_MODE = "sample_100k"` by default, with the same ladder: `smoke`, `sample_100k`, `sample_200k`, `sample_300k`, `full`.
- Use tuned Level 4 from Phase 3.1b as the main non-LLM comparator.

### LLM / Embedding Scope

- Use local MiniLM embedding: `sentence-transformers/all-MiniLM-L6-v2`.
- Do not fine-tune MiniLM or any LLM.
- Do not use API LLM over the full dataset.
- Text input must be neutral table-to-text from real IEEE-CIS features.
- Text input must not contain labels, model scores, risk adjectives, or unsupported business interpretation such as interpreting `ProductCD` as a real product type.
- If MiniLM is unavailable, fallback may be used only if clearly labeled; final LLM claim should prefer MiniLM results.

### Proposed Hybrid Ideas

MVP hybrid candidates:

1. `level5_embedding_similarity_threshold_adjustment`
   - Compute fraud and legitimate embedding prototypes from train rows.
   - Compute cosine similarity or similarity delta for validation/test rows:

```text
sim_delta = cosine(embedding, fraud_prototype) - cosine(embedding, legit_prototype)
```

   - Adjust tuned Level 4 threshold by `sim_delta`, with adjustment strength tuned on validation only.

2. `level5_hybrid_score_threshold`
   - Combine LightGBM probability and embedding similarity:

```text
hybrid_score = sigmoid(logit(lightgbm_score) + w * normalized_sim_delta)
```

   - Tune `w` and threshold policy on validation only.

3. `level5_meta_policy_small`
   - Optional small meta-learner using features such as:
     - LightGBM score
     - embedding similarity delta
     - `TransactionAmt` or amount-bin id
   - To avoid test leakage, train the meta-learner only on train if train scores are available; otherwise split validation into `meta_train` and `meta_validation`, then evaluate once on test.

### Error Analysis

Phase 3.2 must include disagreement analysis:

- Tuned Level 4 catches fraud but Level 5 misses.
- Level 5 catches fraud but tuned Level 4 misses.
- Level 5 reduces false positives that tuned Level 4 blocks.
- High-cost false negatives and high-cost false positives.

### Claim Guard

If Level 5 does not beat tuned Level 4, the report must state this honestly:

```text
MiniLM embedding did not improve the tuned dynamic policy under this run mode; it remains an ablation.
```

No claim may say LLM is better unless Level 5 metrics support it.
</decisions>
