# Phase 3.2 Summary: LLM-Assisted Hybrid Policy

## What Was Built

Created `notebooks/05_llm_hybrid_policy.ipynb` for Level 5 of the five-level evaluation framework.

The notebook:

- loads Phase 2 per-row LightGBM scores;
- loads tuned Level 4 policies from Phase 3.1b;
- rebuilds neutral IEEE-CIS table-to-text rows;
- loads or creates Phase 3.2 embeddings with `sentence-transformers/all-MiniLM-L6-v2` when available;
- falls back to TF-IDF/SVD only for local smoke verification;
- computes train-only fraud and legitimate embedding prototypes;
- implements `level5_embedding_similarity_threshold_adjustment`;
- implements `level5_hybrid_score_threshold`;
- selects Level 5 candidates on validation only;
- evaluates frozen selected candidates on test;
- compares Level 5 directly against tuned Level 4;
- writes Level 4 vs Level 5 disagreement cases and figures.

## Colab MiniLM Verification Result

Notebook 05 was executed on Colab with `RUN_MODE="sample_100k"` and the downloaded outputs now record the intended MiniLM backend.

Backend used:

```text
embedding_backend_used = minilm
```

The run verifies the notebook flow, leakage checks, alignment, candidate tuning, output writing, and comparison logic using `sentence-transformers/all-MiniLM-L6-v2` embeddings.

Selected MiniLM Level 5 result:

| Cost | Selected Level 5 | Test Total Cost | Delta vs Tuned Level 4 |
|---|---|---:|---:|
| Cost-A | similarity threshold adjustment, gamma 0.00 | 20,332.934777 | 0.0 |
| Cost-B | similarity threshold adjustment, gamma 0.00 | 40,665.869555 | 0.0 |
| Cost-C | similarity threshold adjustment, gamma 0.00 | 99,834.099649 | 0.0 |

Because the validation selector chose `gamma = 0.00`, Level 5 matched tuned Level 4 exactly on Cost-A/B/C. This is valid MiniLM evidence for Phase 3.2, but it is not evidence that the simple Phase 3.2 LLM similarity policy improves business cost. This result is the reason Phase 3.3 was planned as a stronger Level 5 v2.
