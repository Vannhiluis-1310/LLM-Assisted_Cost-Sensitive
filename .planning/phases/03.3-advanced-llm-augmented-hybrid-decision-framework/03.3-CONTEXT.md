# Phase 3.3 Context: Advanced LLM-Augmented Hybrid Decision Framework

## Phase Boundary

Phase 3.3 extends Phase 3.2. It does not restart the project and does not replace the completed Level 4 tuning work.

The goal is to create a stronger Level 5 method in a new notebook:

```text
notebooks/06_llm_augmented_hybrid_v2.ipynb
```

The phase should test whether higher-quality MiniLM embeddings and stronger hybrid decision policies can beat tuned Level 4 on business cost.

## Locked Decisions

- Use the same IEEE-CIS dataset and the same `TransactionID` join rule.
- Use the same time-based split and `RUN_MODE` contract as Phase 2/3.1b/3.2.
- Start with `RUN_MODE = "sample_100k"`.
- Run high-quality MiniLM embeddings on Colab, preferably with GPU.
- Primary embedding model: `sentence-transformers/all-MiniLM-L6-v2`.
- Optional alternative embedding model: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
- Notebook 06 must compare against tuned Level 4 from Phase 3.1b and Level 5 v1 from Phase 3.2.
- The target is for Level 5 v2 to beat Level 4 on Total Cost / Cost Saving in at least 2 of 3 cost settings.
- That target is not a guaranteed claim. If results do not support it, the report must state the limitation honestly.

## Leakage-Safe Adjustment

The user suggested computing a fraud prototype from validation fraud samples. To keep the work defensible:

- Main prototype must be computed from train fraud samples only.
- Validation labels may be used only for tuning weights, thresholds, and candidate selection.
- A validation-prototype diagnostic can be included only as a clearly labeled ablation, not as the main claim.
- Test labels must never be used for prototypes, threshold tuning, meta-policy training, or candidate selection.

## Candidate Ideas

1. Fraud prototype similarity:
   - compute fraud and legitimate prototypes from train embeddings;
   - score each transaction by cosine similarity to fraud prototype, or fraud-minus-legit similarity delta;
   - use similarity to adjust tuned Level 4 thresholds.

2. Hybrid score fusion:
   - combine LightGBM probability, embedding similarity, and normalized amount;
   - tune fusion weights on validation only.

3. Meta-learner:
   - train Logistic Regression or small MLP on compact features;
   - inputs may include LightGBM score, similarity features, reduced embedding vectors, amount, amount bin, and time features.

4. Contextual threshold adjustment:
   - use embedding similarity/outlier signals to lower or raise dynamic thresholds;
   - keep threshold adjustment clipped and validation-tuned.
