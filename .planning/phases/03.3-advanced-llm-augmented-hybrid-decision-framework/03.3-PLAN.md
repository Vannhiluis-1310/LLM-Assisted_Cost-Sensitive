# Phase 3.3 Plan: Advanced LLM-Augmented Hybrid Decision Framework

<objective>
Build a stronger Level 5 v2 notebook that uses real MiniLM embeddings and multiple leakage-safe hybrid decision policies. The target is to beat tuned Level 4 on Total Cost / Cost Saving in at least two of three cost settings, while preserving honest reporting if the target is not reached.
</objective>

## Scope

### MVP

- Create `notebooks/06_llm_augmented_hybrid_v2.ipynb`.
- Reuse Phase 2 and Phase 3.1b artifacts for the same `RUN_MODE`.
- Reuse Phase 3.2 MiniLM cache if available, otherwise regenerate MiniLM embeddings.
- Improve neutral table-to-text serialization without risk wording or label leakage.
- Implement three Level 5 v2 candidate families:
  - train-only fraud prototype similarity;
  - hybrid score fusion;
  - compact Logistic Regression meta-learner.
- Tune all weights, thresholds, and candidate choices on validation only.
- Evaluate frozen choices on test.
- Compare directly against:
  - tuned Level 4 guarded selector from Phase 3.1b;
  - Level 5 v1 from Phase 3.2 when available.
- Save metrics, selected policies, disagreement analysis, metadata, and figures.

### Stretch Goal

- Add a small 2-layer MLP meta-learner if Logistic Regression does not improve validation cost.
- Add validation-prototype diagnostic ablation, clearly labeled as diagnostic and not used for the main claim.
- Add model-agnostic permutation-style feature importance for meta-policy inputs.

### Out of Scope

- No LLM fine-tuning.
- No API LLM over the full dataset.
- No RAG, multi-modal learning, Federated Learning, synthetic data, phishing, IDS, malware, or fake-review scope.
- No PPO/A2C.
- No test tuning.
- No claim that LLM is better unless test results support it.

## Candidate Policies

### Candidate A: Train-Only Fraud Prototype Similarity

Policy names:

```text
level5_v2_train_fraud_prototype_adjustment
level5_v2_train_fraud_minus_legit_adjustment
```

Compute from train only:

```text
fraud_prototype = mean(embedding_train[y_train = 1])
legit_prototype = mean(embedding_train[y_train = 0])
sim_fraud = cosine(embedding, fraud_prototype)
sim_delta = cosine(embedding, fraud_prototype) - cosine(embedding, legit_prototype)
```

Adjust tuned Level 4 thresholds:

```text
threshold_v2 = clip(threshold_level4 - gamma * z(sim_delta), 0, 1)
```

Tune `gamma` on validation only:

```python
GAMMA_GRID = [-0.30, -0.20, -0.10, -0.05, 0.00, 0.05, 0.10, 0.20, 0.30]
```

### Candidate B: Hybrid Score Fusion

Policy name:

```text
level5_v2_hybrid_score_fusion
```

Compute:

```text
fusion_score = sigmoid(
    w0
    + w_lgb * logit(lgb_prob)
    + w_sim * z(sim_delta)
    + w_amt * z(log1p(TransactionAmt))
)
```

Tune weights on validation only using a small grid, not unconstrained optimization:

```python
W_LGB_GRID = [0.75, 1.00, 1.25]
W_SIM_GRID = [-1.0, -0.5, 0.0, 0.5, 1.0]
W_AMT_GRID = [-0.5, 0.0, 0.5]
```

Then tune threshold on validation for each cost setting.

### Candidate C: Compact Meta-Learner

Policy name:

```text
level5_v2_logistic_meta_policy
```

Inputs:

- `logit(lgb_prob)`
- `sim_fraud_z`
- `sim_delta_z`
- `log1p(TransactionAmt)_z`
- amount-bin id / one-hot
- optional time features if already available without leakage
- optional reduced MiniLM embedding components

Important correction:

- `all-MiniLM-L6-v2` embeddings are normally 384-dimensional, not 768-dimensional.
- For RAM safety, use raw similarity features first.
- If using full embedding vector, reduce with `TruncatedSVD` or PCA fit on train only, e.g. 32 or 64 components.

Training:

- Train Logistic Regression on train rows if aligned train LightGBM scores are available.
- If train scores are unavailable, train on the first half of validation and tune on the second half; test remains untouched.
- Tune final threshold on validation only.

Stretch:

```text
level5_v2_mlp_meta_policy
```

Use only if Logistic Regression fails to improve validation cost and Colab RAM is stable.

### Candidate D: Contextual Outlier Threshold Adjustment

Policy name:

```text
level5_v2_contextual_outlier_adjustment
```

Compute train embedding centroid and distance:

```text
outlier_score = 1 - cosine(embedding, train_legit_centroid)
```

Then lower threshold only when both conditions hold:

```text
sim_delta_z > selected_sim_cutoff
outlier_score_z > selected_outlier_cutoff
```

Tune cutoffs and adjustment size on validation only.

## Selection Rule

For each cost setting:

1. Evaluate tuned Level 4 comparator.
2. Evaluate all Level 5 v2 candidates on validation.
3. Select the candidate with lowest validation Total Cost.
4. Tie-break:
   - lower FP Cost;
   - higher fraud Recall;
   - higher fraud Precision;
   - simpler policy:

```text
prototype adjustment < hybrid score fusion < logistic meta-policy < MLP
```

5. Apply frozen selected candidate to test.

## Performance Target

The aspirational target is:

```text
Level 5 v2 beats tuned Level 4 on test Total Cost / Cost Saving in at least 2 of 3 cost settings.
```

This is a target, not an automatic claim. If the target is not met, the notebook must state:

- which candidate won validation;
- whether it generalized to test;
- whether MiniLM helped or not;
- that the main contribution remains Level 4 if Level 5 v2 does not improve test cost.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| MiniLM not available locally | Run on Colab; fallback only verifies flow |
| Embedding adds noise | Keep simple candidate families and validation-only selection |
| Overfitting validation | Keep grids small; report validation vs test gap |
| Meta-learner leaks labels | Use train labels for fitting and validation labels only for tuning; test report-only |
| RAM pressure on Colab | Start with similarity features; use reduced embeddings before full embedding vectors |
| Level 5 v2 still loses | Report honestly; keep Level 4 as main contribution |
