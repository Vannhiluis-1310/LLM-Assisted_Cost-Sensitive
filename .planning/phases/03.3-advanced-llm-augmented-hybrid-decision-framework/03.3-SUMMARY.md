# Phase 3.3 Summary: Advanced LLM-Augmented Hybrid Decision Framework

## What Changed

Created `notebooks/06_llm_augmented_hybrid_v2.ipynb` as the separate Phase 3.3 notebook for Level 5 v2.

The notebook reuses the proven Phase 3.2 data/path/embedding setup, but replaces the simple Level 5 policy with an advanced hybrid decision framework:

- improved neutral table-to-text serialization using real IEEE-CIS fields only;
- `phase33_*` embedding cache and result outputs, separate from Phase 3.2;
- train-only fraud and legitimate embedding prototypes;
- richer similarity features: fraud similarity, legit similarity, fraud-minus-legit delta, outlier distance, and train-fitted z-scores;
- validation split into `validation_fit` and `validation_tune` so the meta-policy can be fit without using test;
- Level 5 v2 candidate families:
  - train-only prototype threshold adjustment;
  - fraud-minus-legit threshold adjustment;
  - hybrid score fusion using LightGBM score, embedding similarity, and amount;
  - compact Logistic Regression meta-policy;
  - contextual outlier threshold adjustment;
- validation-only candidate selection per cost setting;
- frozen test evaluation after selection;
- Level 4 vs Level 5 v2 comparison and 0/3, 1/3, 2/3, or 3/3 win-count claim guard;
- disagreement analysis focused on changed actions and row-level cost delta.

## Leakage Controls

- `isFraud`, `TransactionID`, and `TransactionDT` are excluded from text features.
- Text audit checks label/model-score/risk wording.
- Prototypes and z-score parameters are fit on train only.
- Meta-policy is fit on `validation_fit` because train LightGBM scores are not available in the Phase 2 score file.
- Candidate thresholds/weights are selected on `validation_tune`.
- Test is used only after the selected candidate is frozen.
